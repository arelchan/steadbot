# Landscape / 结构图类页面 质量自检与优化

> **⚠ 前置:** 做"产业全景图"类页面前,**必须先读 [`landscape-skeleton.md`](landscape-skeleton.md)**
> 选定骨架。本清单只适用于骨架 = **「A 分层栈 / landscape-map 三层 tier」** 的页面;
> 其他骨架(价值流横轴 / 客户矩阵 / 研发管线 / 生态网络)不要套用本清单。
>
> 适用：`landscape-map` 模板那类页面 —— 三层 tier × 多卡片 × 卡内 chip
> （圆角胶囊小块）的纯 CSS 结构图（**软件 / AI / SaaS 类的分层栈**:互联网产品全景 /
> AI 技术栈 / 云计算分层架构）。
>
> 这套清单来自十几轮反复失败的真实教训。生成这类页面后，**逐条对照
> 执行，不要跳过、不要凭感觉判断"应该没问题"**。

## 一、踩坑黑名单（最重要 —— 这些坑反复踩过）

1. **绝不写 JS 测卡片尺寸去反推 chip 字号做"自适应铺满"**。
   cqh / 二分逼近 / 全局系数 / logo 异步重算这条路是死结，试了十几轮全失败。
   chip 字号用 **CSS 固定值**（如 15px / 嵌套 13px），靠数据规范保证不截断。
   JS **只允许注入 logo**，绝不测量卡片尺寸（连统一宽度也不做——这正是
   过去死结的一环）。chip 宽度交给 CSS（`flex-wrap` 居中 + `align-items:center`），
   不靠 JS 测量对齐。

2. **绝不只截单个 tier 的局部图就判"通过"**。三层挤一起、整体偏上、下方
   大片留白、虚线错位 —— 这些全局问题在单 tier 局部图里**永远看不出来**。
   **每次必须看完整全页截图**（1600×900 完整 clip），用肉眼确认。

3. **绝不轻信自己写的 scrollWidth / scrollHeight / Range 截断检测**。在这套
   嵌套 flex/grid 结构里，这类自写检测会**系统性误判**——实测多次"数字报裁切"
   但完整全图肉眼**完全正常**（嵌套 flex/grid 的 scroll* 会把内部布局算进去而误报）。
   检测数字一律不信，**验证只信完整全页截图肉眼**。

4. **模板注释头 / 任何说明文字里绝不出现裸 `<style>` 字面量**。
   否则正则提取 style 块时会从注释里那个 `<style>` 字样开始误抓，
   把大段中文说明当 CSS → CSS 解析崩溃 → 规则全失效 → 三层挤一起。
   提取时用 `re.findall(r'<style>(.*?)</style>', s, re.S)[-1]`（取最后一对）。

5. **截图前绝不只用固定 `wait_for_timeout`**。logo 是异步加载的，
   必须**轮询所有 `<img>.complete` 都为 true**（最多等 20s）再截，
   否则截到一堆没加载完的空 logo。

6. **英文长词 / "A / B" 合并项绝不硬塞一个 chip**。从数据层就拆/简写
   （见下方数据规范），渲染层不负责"塞下超长文案"。

7. **列数交给 CSS + 数据，不写 JS 动态列数**（旧的 `setColumns()` 已从模板移除）。
   chip 在卡内用 `flex-wrap` 横向流式排列、`align-items:center` 居中，自然换行，
   不需要 JS 按 chip 数 + span 去算 `grid-template-columns`。要避免"第二列挂空 /
   单 chip 孤行"的难看效果，靠**数据自律**：简单卡 ≤ 4 chip、嵌套小格 ≤ 3 chip，
   chip 短词化，让一两行内排得满而不溢。窄卡 chip 多就自然纵向多排一两行，
   由 tier 等高封顶兜住，不会溢出。

8. **三 tier 用 `grid-template-rows:1fr 1fr 1fr` 等高封顶，不写 JS 动态 tier 高度**
   （旧的 `redistributeTierHeights()` 已从模板移除）。等高是**有界、永不溢出**的：
   每 tier 高度固定为 diagram 的 1/3，内容必须在数据层就压进这个高度。
   不要再去按"各 tier 最大单卡行数"加权算 `5fr 3fr 3fr` —— 那是测量重排的老路。
   保证不裁切的办法是**控制每卡 chip 数**（见数据规范），而不是让某 tier 撑高。

9. **`--span:N` 是 HTML 静态写死的，不写 JS 动态重分 span**（旧的
   `redistributeSpans()` / `eqGroup()` 已从模板移除）。同 tier 各卡 span 合计 == 12
   这条铁律在**写 HTML 时一次定好**，不靠 JS 运行时重算。内容量差异大时，在
   数据/HTML 阶段就把 span 调匀（多 chip 卡给大 span、少 chip 卡给小 span），
   而不是渲染后让 JS 测量再重排。
   核心思路（来自用户洞察）：**视觉舒服的关键是"内容密度分布均匀"，
   不是几何尺寸完全相等** —— 这个"均匀"在静态 span 里手动配好即可，
   不出现"一卡 4 个、邻卡 1 个"的反差就行。

10. **嵌套小格（行业应用类）绝不空荡 + chip 绝不贴边**。嵌套 `.ls-cell`
    里若只有 1-2 个 chip，会显得空且与卡片高度不匹配 → **每个嵌套小格
    至少 3-4 个 chip**，让小格饱满。同时 `.ls-body` 左右 padding 至少
    `12px`（不能只 `6px`），否则 chip 紧贴卡片边界缺呼吸感。
    数据层规范：列子分类时多想几个代表实体（金融除工行/平安，再加招行/
    蚂蚁；医疗除联影，再加迈瑞/推想等）。

## 二、数据规范清单（生成前 / 生成中执行 —— 从源头杜绝问题）

PPT 文案本就不该超长。截断的根治在数据层，不在渲染层：

- [ ] 每个 chip 一个**短词**：≤ 4~5 个汉字 / 一个英文术语。
- [ ] 「A / B」「A + B」这类合并项 → **拆成多个独立 chip**（同类就多放
      几个 chip，不要硬塞一个）。例：`ItemCF / UserCF` → 两个 chip。
- [ ] 英文用业内通用**简写**：DSSM、MMoE、ANN、DCN…（不写全称）。
- [ ] 英文长公司名 → 业内通用**中文简称**：`Momenta` → `魔门塔`、
      `Pony.ai` → `小马`（与同卡其他公司中文名风格一致）。
- [ ] landscape-map 结构铁律：**每个 tier 的 `--span` 合计必须 == 12**，
      否则 grid 折行 → 大片留白。改 span 后逐 tier 求和验证。
- [ ] **嵌套小格（`.ls-cell`）至少 3-4 个 chip**。子分类列代表实体时多想
      几个（如金融：工行/平安/招行/蚂蚁；医疗：联影/迈瑞/推想/鹰瞳），
      避免每小格只有 1-2 chip 显得空荡、与卡片高度不匹配。

## 三、渲染自检清单（生成第一版后必做 —— 看完整全图，逐条核）

用 Playwright 渲染（注入 `:root{--fit:1}`、隐藏 nav），**等所有 img.complete
后截完整全页 1600×900 图**，然后逐条肉眼核对：

- [ ] **三层均匀分布、撑满**：tier 三等分占满区域（约 ~74% slide 高），
      不挤在上半部、底部无大片留白。（`.diagram-landscape`:
      `flex:1 1 auto; display:grid; grid-template-rows:1fr 1fr 1fr`）
- [ ] **三层间距正常**：层间有清晰间隔（`--tier-gap:22px` + `row-gap`），
      不贴在一起。
- [ ] **分割虚线在层间隙中央**：`.lm-row+.lm-row::before` 用
      `top:calc(-1*var(--tier-gap)/2)`，不是死值 margin-top。
- [ ] **chip 排布整齐居中、没被纵向拉伸**：chip 由 CSS `flex-wrap` 居中
      （`align-items:center`），宽度随内容、字号是 CSS 固定值。重点看 chip
      **没有被 flex 默认 `stretch` 拉成 2 倍高**（这正是 `align-items:center`
      要防的），各 chip 高度一致、横向流式换行自然。不需要、也不该有 JS 去测量统一宽度。
- [ ] **零文字截断**：肉眼逐 tier 看，没有"小··""Mo··"这种被裁的。
- [ ] **logo 真加载**：截图前 img 全部 complete；个别公司 Clearbit 无收录
      回退首字母色块是正常的，不算 bug。
- [ ] **无 chip 重叠、无纵向溢出、无 JS 报错**（pageerror 为空）。
- [ ] **CSS 真生效自检**：computed `display` 应为 `grid` 而非 `block`。
      若是 block → 多半是规则 4 的 `<style>` 字面量导致 CSS 解析崩了。
- [ ] **chip 流式排布正常（静态结果）**：chip 用 `flex-wrap` 自然换行居中，
      内容少的卡一两行排满即可、不留尴尬空列；内容多的窄卡多排一两行也被
      tier 等高兜住。这里**不该看到任何 JS 动态算列数的痕迹**——模板里已无
      `setColumns()`，`.lc-body` 的列布局完全由 CSS 决定。
- [ ] **span 静态合规自检**：`--span` 是 HTML 写死的，computed 应与源码一致
      （不会被运行时改动——模板里已无 `redistributeSpans()` / `eqGroup()`）。
      逐 tier 把各卡 `--span` 求和，应 == 12；内容密度肉眼看均匀，无"一卡塞满、
      邻卡空荡"的反差。
- [ ] **三 tier 视觉等高（静态封顶）**：`.diagram-landscape` 的 `gridTemplateRows`
      应就是 `1fr 1fr 1fr`，三层视觉等高、各占 1/3，**没有纵向溢出**。
      不该看到某 tier 被加权撑高（模板里已无 `redistributeTierHeights()`）。
- [ ] **嵌套卡底部 chip 没被裁**：tier 等高封顶下，重点看内容最多的那张
      嵌套卡——它最后一行 chip 是否完整、没被 1/3 tier 高度切掉。若被裁，
      回数据层删 chip（每嵌套小格 ≤ 3、简单卡 ≤ 4），**不要去改 CSS 撑高 tier**。
- [ ] **chip 没被纵向拉伸**：肉眼确认 chip 高度一致、没有个别 chip 被 flex
      `stretch` 拉成约 2 倍高（`align-items:center` 已防止，这里复核结果）。
- [ ] **嵌套小格 chip 不贴边**：量 `.ls-cell` 内第一个 `.lm-item` 距小格
      左右边界应 ≥ 12px。`.ls-body` 左右 padding 至少 `12px`。

## 四、LLM 二次复查流程（自检发现问题时）

自适应/渲染逻辑**不要改**（它是稳定的）。问题几乎都出在数据：

1. 全图发现某 chip 截断 / 某卡过挤 → **回到第二节数据规范**，精简该卡文案、
   拆 chip、英文换简写，**重新 build**。不要去改渲染 CSS/JS。
2. 改完数据后**重新执行第三节渲染自检全清单**（再看一次完整全图）。
3. 直到全图肉眼确认所有项通过，才算完成。

## 一句话总结

**数据层规范内容（短词/拆块/简写）+ 渲染层固定尺寸（不靠 JS 自适应）
+ 验证只信完整全图肉眼（不信局部图和自写检测）。** 这三条守住，
就不会重蹈那十几轮的覆辙。
