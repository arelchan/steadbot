# 汇报质量铁律 — 交付前必过的 14 关

> 这套清单来自真实做汇报 PPT 时反复踩的坑。**生成 deck 后、交付前，逐条对照执行**，
> 不要跳过、不要凭感觉判断"应该没问题"。
>
> 分四关，越往后越靠后期：**内容可信 → 表达清晰 → 版面克制 → 工艺可靠**。
> 每条都给 ❌ 反例 → ✅ 正解。
>
> 配套：版面深法（金字塔 / F-Z 路径 / 留白比例）见 [`layout-principles.md`](layout-principles.md)；
> 结构图类页面（分层栈 / landscape-map）的专项自检见 [`landscape-qa.md`](landscape-qa.md)。

---

## 一、内容 · 可信（这页的数字能不能信）

### 1. 确认信源
每个关键数字都要能回答"哪来的"。

- ❌「市场年增 155%」——读者第一反应：你编的？
- ✅「市场年增 155%（Gartner/IDC 三方中位数）」——括号里给出处。
- 拿不准就写"**约 / 估算**"，或者**干脆删**。一个没出处又不敢标"估算"的数字，是负资产。

### 2. 单一真相（Single Source of Truth）
同一个指标，全篇只定义一次、之后都引用它。

- ❌ 正文写"CIT 10%"、脚注却说"25%"——读者懵，信任崩。
- ✅ 一个数**定义一次、全篇引用**；币种单位统一（要么全 ¥，要么开篇标清"1 USD ≈ ¥7.2"再混用）。
- 自查：把全篇同名指标列出来，值必须一致。

### 3. 事实与观点分离
别把"建议"伪装成"事实"。

- ❌「用 EOR 最好」——这是观点，但写得像定论。
- ✅「EOR 3–7 天上线（**事实**）；1–20 人团队建议用它（**观点**）」——事实给依据，观点亮立场。
- 句式上：事实用数字 / 来源，观点用"建议 / 我们认为 / 更适合"。

## 二、表达 · 清晰（读者看不看得懂）

### 4. 替读者扫障碍
术语首次出现，给一句人话 + 一个例子。读者不该为看懂你的页面去查字典。

- ❌ 标题甩一串「WFOE / DTA / FSIE / Pillar Two」不解释。
- ✅ 首现就翻译：「WFOE = 境外母公司全资的中国公司，可合法发工资、缴社保」。
- 缩写第一次出现写全称 + 缩写，之后才用缩写。

### 5. 结论先行
标题写**结论**，不写**主题**。读者扫标题就该拿到判断。

- ❌「市场分析」「为什么是现在？」——这是目录，不是结论。
- ✅「AI 安全是 12–18 个月窗口：海外已验证、国内还空白」——一句话给出 so-what。
- 检验：把所有页标题抽出来连读，应该是一条完整论证链，而不是一堆名词。

### 6. 直白也要专业
不水（口语化到没信息）、不硬（满屏术语没人味）。

- ❌「反正得交点税」（太水）/ 整页堆术语（太硬）。
- ✅「公司利润交 25% 企业所得税——赚 100 万交 25 万」：专业概念 + 一个算给你看的例子。

### 7. 分层供给
卡面只放结论级信息，细节折叠进 hover / 附录。外行不被淹、内行能下钻。

- ❌ 把"社保基数 / PE 常设机构天数 / 税收协定条款"全平铺在卡面。
- ✅ 卡面只留「3–7 天上线」；细节进 hover 提示或文末附录页。
- 一张卡的"第一眼信息" ≤ 3 个，其余靠下钻。

## 三、版面 · 克制（看不看得清、乱不乱）

> 版面的**深层法则**（金字塔结构、F/Z 阅读路径、标题/主体/footer 比例）见
> [`layout-principles.md`](layout-principles.md)。这里只列最常翻车的 5 条硬规矩。

### 8. 不留空白
卡片高度和内容要么撑满、要么贴合，别"字堆顶部、下半张空着"。

- ❌ 卡片拉满高、内容只占上 1/3；描边框里就两行字，框大得空旷。
- ✅ 内容**上下撑满**（加证据 / 留白均分），或把卡**缩到内容高度再居中**。
- 注意：留白本身不是错，**失衡的留白**才是——上挤下空 = 没设计。

### 9. 可读优先
字号为"投屏 / 手机"定，不为"你盯着屏幕看"定。

- ❌ 正文 10px、脚注 9px——投影到三米外糊成一片。
- ✅ **正文 ≥ 14px、脚注 ≥ 11px**，标题三米外能读。
- ⚠ 横屏 deck 是 1600×900 设计稿等比缩放：设计稿里的 px 会随投屏宽度缩放
  （1920 投屏 ×1.2、1280 屏 ×0.8）。本项目字号令牌见 `common.css` 的 `--fs-*`
  （`--fs-body:13px / --fs-mini:11px`）——**脚注别再往 11px 以下走**，正文优先用 `--fs-body` 及以上。
  竖屏（手机）字号更大，见 `portrait.css` 的 `--fs-*`。

### 10. 对齐见功夫
对齐是"专业感"最廉价又最值钱的来源。

- ❌ 三张卡高低不齐、金额左右乱跳、列边参差。
- ✅ **同行等高**（flex/grid `align-items:stretch`）、**金额右对齐 + 等宽数字**、**列边对齐**。
- 金额 / 数字列用工具类 **`.num`**（`common.css` 已提供：`tabular-nums` + 右对齐），
  保证个十百千位**纵向对齐**、不跳动。

### 11. 一页一事
一页一个锚点。讲不完就拆页（页很便宜，混在一起很贵）。

- ❌ 一页同时讲市场 + 竞品 + 客户 + 风险。
- ✅ 拆成四页，每页一个锚点、一个结论。
- 检验：这页"一句话主旨"写不出来，就说明它在讲多件事，该拆。

### 12. 留出节奏
连续高密度会让读者疲劳、信息反而留不下。

- ❌ 连着六页高密度数据表。
- ✅ 中间插一页低密度"**3 个结论**"喘息页（大字、留白、就三句话）。
- 节奏参考：每 3–4 页密集内容，给 1 页低密度小结 / 金句。

## 四、工艺 · 可靠（交付经不经得起）

### 13. 眼见为实
别"代码写完应该没问题"就交付。**看到**才算数。

- ❌「逻辑上没问题」直接交。
- ✅ 两条腿走路：
  1. **逐页截图肉眼过**：`python3 export_images.py dist/*.html`（或横屏用 `export_pdf.py`），
     一页页看溢出 / 留白 / 错位 / 术语漏定义。
  2. **跑机检脚本**：`python3 check_deck.py`——自动报字号过小 / 币种单位混用 / 数字缺信源 / 术语清单。
- ⚠ **溢出 / 留白 / 对齐 这类只信肉眼截图，别信自写的 `scrollWidth/scrollHeight` 检测**：
  在嵌套 flex/grid 结构里这类检测会**系统性误判**（血泪教训详见 [`landscape-qa.md`](landscape-qa.md)）。
  所以 `check_deck.py` **只做不依赖布局测量的检查**，布局问题一律交给截图。

### 14. 经得起改
结构要禁得起"临时插一页 / 改一个引用"。

- ❌ 页码、引用全硬写——插一页满盘皆改。
- ✅ **页码构建期自动算**（本项目已实现：`common.js` 按 `.slide` 数量自动生成
  counter "N / 总数" 和导航点，插页自动更新，**不要在模板里硬写页码**）；
  **引用指向锚点 ID**（`<a href="#slide-risk">`），别写死"见第 5 页"——插页后页号会变、ID 不变。

## 交付前 Checklist（逐条打勾，全过才发）

**内容**
- [ ] 每个关键数字有信源，或明确标了"约 / 估算"
- [ ] 同一指标全篇同一个值；币种 / 单位统一（混用处标了换算）
- [ ] 事实与观点分开写，建议没伪装成定论

**表达**
- [ ] 术语首现有"人话 + 例子"；缩写首现给全称
- [ ] 每页标题是**结论**不是主题；连读成一条论证链
- [ ] 卡面信息分层，第一眼信息 ≤ 3 个

**版面**
- [ ] 没有"上挤下空"的失衡留白
- [ ] 正文 ≥ 14px、脚注 ≥ 11px（脚注没低于 `--fs-mini`）
- [ ] 同行等高、金额 `.num` 右对齐、列边对齐
- [ ] 一页一事；高密度之间有低密度喘息页

**工艺**
- [ ] 跑了 `check_deck.py`，无 ERROR（WARN 逐条确认）
- [ ] **逐页截图肉眼过了一遍**，无溢出 / 留白 / 错位
- [ ] 页码没硬写（走自动）；引用指向 ID 不指向页号
