# 视觉交付验收

## 目的

模型看不见自己做出来的东西。生成的图、渲染的页面、导出的 PPT，在交出去之前都只是一串路径，
好不好看、有没有崩、字有没有被裁掉，只有真的看过才知道。这份手册就是把「看一眼」变成固定动作。

## 何时使用

产出物是给人看的，就走这一遍：

- 画的图、做的海报、生成的头像和素材
- 渲染出来的 PPT / PDF / 文档
- 写完的网页、组件、图表
- 要发给用户的截图

纯文本、代码、数据文件不用走。

## 步骤

1. **先变成能看的文件。** 网页截图，PPT 和 PDF 转成图（`soffice --headless --convert-to pdf`、`pdftoppm -png -r 120`），
   图表先导出成 png。没有文件就没有验收。
2. **用 `see` 打开它。** 一次看一张，多页的至少看首页和内容最密的一页。
3. **照清单挑毛病**，不要笼统地说「看起来不错」：
   - 文字有没有被裁掉、溢出容器、压到图上
   - 中文断行是不是断在词中间，有没有变成竖排或乱码方块
   - 有没有残留的占位符：Lorem ipsum、`{{title}}`、示例数据、默认灰图
   - 对齐和间距：元素是不是各歪各的，边距是不是一边宽一边窄
   - 图片有没有被拉伸变形，比例对不对
   - 深浅对比够不够：浅灰字压在白底上，投影仪上什么都看不见
   - 数字和事实和用户给的对不对得上
4. **挑出毛病就改，改完再看一遍。** 至少一轮。第二轮还有同样的问题，说明做法有问题，换做法，别硬调参数。
5. **交付时给路径和一句话。** 说清是什么、几页/几张、还差什么。别把「我已经检查过了」当成交付内容。

## 需要用户确认的点

- 品牌色、字体、logo：用户没给就别自己发明，问一句，或者先用中性配色做出来给他看。
- 尺寸和用途：印刷、投屏、发朋友圈，三者的比例和分辨率不一样。
- 改到第二轮还不对，把两版都摆出来让用户选，别自己反复猜。

## 注意事项

- 生成图片的模型不认字。海报上的文字自己叠上去（HTML 渲染或 Pillow），别指望模型把字写对。
- 一张图看着糊，先看原始分辨率，不要靠再生成一次碰运气。
- 要透明底就用 rembg 抠，别让模型「画一个透明背景」。
- 验收是给用户看的东西的最后一道，不是给自己加戏：看完没问题就直接交，不用汇报检查过程。
